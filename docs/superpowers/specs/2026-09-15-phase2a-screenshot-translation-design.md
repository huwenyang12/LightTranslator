# LightTranslator Phase 2A 截图翻译设计

日期：2026-09-15  
基线：`v0.1.0` / `e855d2e6c99a5840ea99d2fd72d3f9c47960695e`

## 1. 目标

Phase 2A 将 Phase 1 中的截图翻译占位流程替换为可用的端到端功能：用户通过 `Alt+Q` 或托盘菜单框选屏幕区域，软件在本机完成 OCR，仅将识别出的文字发送给 DeepSeek 翻译，并在原选区的文字位置显示译文。

本阶段强调可用性、隐私和可演进性。结果布局采用“原位基础覆盖”，为 Phase 2B 的背景清理和精细排版保留同一套坐标与渲染结构。

## 2. 已确认的产品决策

- OCR 使用 PaddleOCR 模型，通过 ONNX Runtime 直接在 C# 进程内运行，不依赖 Python。
- PP-OCRv5 Mobile 通用 OCR 模型随应用发布，一套模型直接支持中文、英文和日文。
- 截图只在本机内存中处理，不保存、不上传；DeepSeek 只接收 OCR 文字和语言参数。
- 译文以半透明块显示在 OCR 原文字位置，每个块只显示译文。
- 结果层保持置顶，不自动消失；单击覆盖层、按 `Esc` 或再次按 `Alt+Q` 时关闭。
- 同一时间只允许一个截图翻译任务。
- Phase 2A 只支持单显示器内框选，不支持跨显示器框选。

## 3. 用户流程

1. 用户按 `Alt+Q` 或点击托盘菜单“截图翻译”。
2. 软件识别鼠标当前所在显示器，冻结该显示器画面并显示十字光标框选层。
3. 用户拖拽选择区域；按 `Esc` 取消时静默结束。
4. 用户松开鼠标后，选区立即变成置顶结果层，并在中央显示“正在识别…”。
5. 软件在本机执行 OCR，过滤并排序有效文字块。
6. 软件把本次全部有效文字块组成一次带编号的批量翻译请求。
7. 翻译返回后，软件按编号将译文映射回对应 OCR 坐标并绘制半透明译文块。
8. 结果层保持显示，直至用户单击、按 `Esc` 或再次按 `Alt+Q`。

## 4. 系统架构

主流程为：

`快捷键/托盘入口 → 截图任务协调器 → 屏幕冻结与框选 → 本地 OCR → DeepSeek 批量翻译 → 原位译文覆盖层`

### 4.1 ScreenshotTranslationCoordinator

负责完整流程的编排、状态切换和取消，不实现截图、OCR、翻译或渲染细节。

- 同一时间最多持有一个活动任务。
- 新的 `Alt+Q` 请求会取消并关闭当前任务，而不是并行启动第二个任务。
- 任务取消后忽略所有迟到的 OCR 或翻译结果。
- 负责在窗口关闭时释放位图、OCR 结果和取消令牌。

### 4.2 ScreenCaptureService

负责确定鼠标所在显示器、截取该显示器画面，以及提供选区对应的像素图像和坐标信息。

输出至少包含：

- 选区位图；
- 选区相对于目标显示器的像素坐标；
- 目标显示器的屏幕坐标；
- DPI 缩放信息。

Phase 2A 不允许选区跨越显示器边界。

### 4.3 PaddleOcrService

通过 ONNX Runtime 在应用进程内运行检测和识别模型。输出 `OcrBlock` 集合，每个块至少包含：

- 唯一编号；
- 原文字；
- 置信度；
- 相对于选区的像素矩形；
- 对应译文（翻译完成后填写）。

置信度低于 `0.50` 的块不进入翻译和渲染流程。有效块按照从上到下、从左到右排序。

`auto`、`zh`、`en` 和 `ja` 均使用内置 PP-OCRv5 Mobile 通用模型；语言设置用于翻译提示和结果语义，不触发运行时模型下载。

### 4.4 OcrModelProvider

负责定位和校验随应用发布的 OCR 模型资产。

- PP-OCRv5 Mobile 检测模型、通用识别模型和字符字典作为应用内容随发布包提供。
- 启动 OCR 前验证必需文件存在且可读；缺少资产时返回模型不可用错误。
- 运行时不下载 OCR 模型，不向用户目录写入模型文件。

### 4.5 翻译服务

复用现有 DeepSeek 翻译能力，并增加适用于 OCR 块的批量映射协议。

- 一次请求发送本次全部有效文字块，以保留上下文并减少网络往返。
- 每个文字块带稳定编号，响应必须按编号返回。
- 响应缺少某个编号时只跳过对应块，不错配其他译文。
- 请求只包含文字、源语言和目标语言，不包含截图、坐标和本地路径。

### 4.6 ScreenshotTranslationWindow

结果窗口位于原选区的屏幕位置，保持置顶，并包含两层：

1. 冻结的选区截图；
2. 按 OCR 坐标绘制的译文块。

译文块使用深色半透明背景和浅色文字，只显示译文。Phase 2A 不进行背景修复、字体匹配或复杂排版。窗口支持单击、`Esc` 和 `Alt+Q` 关闭。

### 4.7 AppController

继续接收现有快捷键和托盘事件，只调用 `ScreenshotTranslationCoordinator`。OCR、模型加载和结果渲染不得继续堆入 `AppController`。

## 5. 坐标与 DPI

截图与 OCR 使用物理像素坐标，WPF 窗口和控件使用设备无关单位。渲染前必须使用目标显示器 DPI 将以下坐标统一转换：

- 选区相对于显示器的像素坐标；
- 结果窗口的屏幕位置和尺寸；
- OCR 块相对于选区的位置和尺寸。

验收必须覆盖 Windows `100%`、`125%` 和 `150%` 缩放。坐标换算应封装为独立、无 UI 依赖的组件，以便单元测试。

## 6. 状态与错误处理

- **取消框选**：静默结束。
- **正在识别**：选区截图保持显示，中央展示加载状态。
- **未识别到文字**：显示“未识别到文字”。
- **OCR 初始化或推理失败**：显示“文字识别失败，请重试”。
- **API Key 缺失**：显示“请先在设置中配置 API Key”。
- **网络超时、接口限流或翻译失败**：保留选区截图并显示简短错误；不自动无限重试。
- **任务取消**：关闭窗口并忽略迟到结果，不显示错误。

Phase 2A 不提供结果层内的重试按钮。用户关闭后重新按 `Alt+Q` 发起新任务。

## 7. 隐私与日志

- 截图、OCR 原文和译文只存在于内存中，不写入磁盘。
- 截图、OCR 原文、译文和 API Key 不进入日志。
- 日志只记录耗时、识别块数量、模型标识、任务状态和脱敏后的错误类型。
- DeepSeek 只接收 OCR 文字和语言参数。
- API Key 继续使用现有 DPAPI 方案保存到用户本地，不进入源码或发布包。

## 8. 性能目标

- 框选完成后立即显示冻结选区和加载状态，主界面不得假死。
- 在模型已加载、普通网络环境和常见 1080p 局部选区下，从框选完成到译文出现的目标为 `1～2 秒`。
- OCR 推理与网络请求必须异步执行，并支持取消。
- 首次模型初始化时间不计入常规截图翻译性能目标，但必须显示明确状态。

## 9. 测试与验收

### 9.1 自动化测试

- OCR 结果过滤、排序和坐标转换；
- `100%`、`125%`、`150%` DPI 下的像素/WPF 坐标映射；
- 多 OCR 块批量翻译、编号回填及缺失编号处理；
- `Alt+Q`、`Esc` 和单击关闭时的取消行为；
- 取消后迟到结果不能重新显示窗口；
- 内置模型资产定位、完整性检查和缺失模型错误；
- 无文字、API Key 缺失、OCR 失败和网络失败状态；
- 日志不包含截图文字、译文和 API Key；
- Phase 1 现有测试继续全部通过。

### 9.2 人工验收

- 快捷键和托盘菜单均可完成截图翻译；
- 单显示器和双显示器环境；
- Windows `100%`、`125%`、`150%` 缩放；
- 中英混合、纯英文、纯中文截图；
- 中文、英文、日文及中英混合内容的直接识别；
- 无文字、断网、API 错误和任务取消；
- 发布包在未安装 .NET、Python 和 OCR 环境的新电脑运行；
- 发布包不包含开发者 API Key，首次运行用户配置自己的 Key。

## 10. Phase 2A 范围外

以下内容不在本阶段实现：

- 清除原文字背景和图像修复；
- 精确匹配原字体、字号、颜色和排版；
- 跨显示器框选；
- 旋转文字、竖排文字等特殊排版优化；
- 连续监听、翻译历史和截图保存；
- 编辑、复制或导出截图翻译结果。

背景清理和精细原位布局进入 Phase 2B；其他能力在后续版本单独设计。

## 11. 完成标准

当以下条件全部满足时，Phase 2A 可进入验收：

1. 从 `Alt+Q` 和托盘入口都能完成“框选 → OCR → 翻译 → 原位覆盖”。
2. 中文、英文和日文无需额外环境或运行时下载即可离线 OCR。
3. 截图不落盘、不上传，日志和发布包不泄露用户内容或 API Key。
4. 取消、无文字、OCR 失败和翻译失败都有稳定行为，且不会出现迟到窗口。
5. DPI 和双显示器人工验收通过。
6. 新增测试通过，Phase 1 回归测试保持通过，Release 构建无错误。
